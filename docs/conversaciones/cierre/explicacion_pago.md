# Cierre — Explicación de Pago

# Objetivo
Explicar con claridad cómo realizar el pago, sin fricción ni ambigüedad.

# Momento del embudo
Cierre (después de [Confirmación de Pedido](./confirmacion_pedido.md))

# Perfil de cliente relacionado
Transversal.

# Productos relacionados
Los confirmados en el pedido.

# Contexto
El pedido ya está confirmado; toca explicar la forma de pago disponible.

# Conversación ejemplo

Asesor:
Tu pedido quedaría en [precio vigente]. Puedes pagarlo por [método de pago que manejes: transferencia, efectivo contra entrega, etc.]. En cuanto confirmes el pago, te aviso y programamos el envío.

Cliente:
Perfecto, ya hice la transferencia.

Asesor:
¡Genial, gracias! Ya lo confirmo y te aviso apenas esté listo para enviar 🙌

# Variantes de respuesta

- Si el cliente pregunta por más de un método de pago disponible: listar solo las opciones reales que maneja el negocio, sin inventar métodos no disponibles.
- Si el cliente pide comprobante o factura: responder según la práctica real del negocio (no está definida en el catálogo de producto).

# Qué hacer después
Al confirmarse el pago, continuar con [`confirmacion_envio.md`](./confirmacion_envio.md).

# Qué NO decir
- No inventar un precio o método de pago si no se tiene la información exacta y actualizada — mejor confirmar antes de responder que dar un dato incorrecto.
- No presionar con "tienes que pagar ahora mismo para apartar el producto" si no es una política real del negocio.

# Notas comerciales
*(Recomendación comercial, no médica)* Ni el catálogo de producto (`docs/productos/`) ni los perfiles de cliente (`docs/clientes/`) incluyen precios ni métodos de pago — esta información depende enteramente de la operación real del negocio y debe mantenerse actualizada fuera de esta base de conocimiento.
