# Base de Conocimiento — Clientes Vida Divina

> Módulo de conocimiento orientado a **necesidades, objetivos y problemas del cliente** — no a categorías de producto. Complementa al módulo [`docs/productos/`](../productos.md), que está organizado por producto/categoría.
>
> Objetivo: que la IA (o cualquier persona del equipo) pueda leer un solo archivo de perfil y saber exactamente qué preguntar, qué recomendar y qué evitar para ese tipo de cliente, con enlaces directos a las fichas de producto correspondientes.
>
> ¿Buscas en qué momento del embudo se consulta este módulo? Ese criterio vive en [`docs/proceso_de_venta/`](../proceso_de_venta/README.md) — la regla fija es que siempre se consulta `docs/clientes/` antes que `docs/productos/`.

---

## Nota Importante

Esta base de conocimiento se construyó analizando `catalogo 2026.pdf`, que es un **catálogo de producto**, no un documento médico ni un manual de ventas oficial. Por lo tanto:

- **Ingredientes, beneficios y presentaciones** de cada producto provienen directamente del catálogo (ver [`docs/productos/`](../productos.md)).
- **Objeciones comunes, preguntas para identificar al cliente, argumentos de venta, cómo iniciar la conversación, seguimiento recomendado y nivel de prioridad** en cada perfil son **recomendaciones comerciales basadas en buenas prácticas de venta**, no información médica ni guiones oficiales de Vida Divina. No sustituyen el criterio del vendedor ni material oficial de la empresa.
- **Ningún perfil afirma que un producto cura, trata o previene una enfermedad.** El lenguaje se mantiene alineado al catálogo ("apoya", "ayuda a", "promueve un bienestar saludable"). Ante cualquier condición médica diagnosticada, la recomendación es siempre remitir al cliente a un profesional de la salud.
- **Los "Kits recomendados" son sugerencias comerciales de agrupación de productos**, no kits oficiales con nombre o precio definidos por Vida Divina, salvo que se indique lo contrario.
- El perfil [Emprendimiento](./emprendimiento.md) trata sobre la oportunidad de negocio (afiliación), no sobre consumo de producto; el catálogo analizado no incluye plan de compensación.

## Cómo está organizada esta base de conocimiento

Cada perfil de cliente responde a una **necesidad u objetivo**, no a una categoría de producto. Un mismo producto puede aparecer en varios perfiles (por ejemplo, Reishi Capsules aparece en Bienestar General, Sistema Inmunológico y Longevidad), porque un mismo producto puede resolver necesidades distintas según el cliente.

Cada archivo de perfil sigue esta estructura fija:

`Descripción · Objetivo principal · Problemas que normalmente presenta · Motivaciones · Objeciones comunes · Productos recomendados · Kits recomendados · Productos complementarios · Productos que NO son prioridad · Cómo iniciar la conversación · Preguntas para identificar al cliente · Argumentos de venta · Beneficios que más le interesan · Seguimiento recomendado · Posibles ventas futuras (cross-selling) · Palabras clave · Nivel de prioridad de este perfil para el negocio`

## Notas de mantenimiento

- **Relación con el módulo de productos:** todos los enlaces de "Productos recomendados" apuntan a fichas reales dentro de [`docs/productos/`](../productos.md). Si se agrega un producto nuevo allí, revisar si corresponde añadirlo también a uno o varios perfiles de cliente aquí.
- **Al crear un nuevo perfil:** usar la misma plantilla de 17 secciones (ver arriba), guardar el archivo en `docs/clientes/` con nombre en `snake_case`, y añadirlo a la tabla de índice y al "mapa rápido" de este README.
- **Evitar duplicar contenido:** si una necesidad ya está cubierta por un perfil existente, ampliar ese perfil en vez de crear uno nuevo casi idéntico. Los perfiles se diseñaron para no solaparse (por ejemplo, Cuidado Personal vs. Belleza y Anti-Edad están separados por ticket/audiencia, no seria necesario dividir más).
- **Todo dato ausente en el catálogo** debe marcarse explícitamente como "No especificado" en la ficha del producto, y las secciones de proceso de venta (objeciones, preguntas, argumentos, seguimiento) deben mantenerse etiquetadas como recomendación comercial, no médica.
